# layout graph

## architecture

_"지능형 학술 문서 생성 시스템: 데이터 파이프라인 아키텍처"_

전체 데이터 흐름은 기획(LLM) ➡️ 설계(GNN) ➡️ 시공(LLM/CLIP) ➡️ 렌더링의 4단계로 구성됩니다.

---

### Step 1. 기획: 시맨틱 그래프 생성 (Semantic Graph Generation)

사용자의 파편화된 원시 데이터를 분석하여, 학술 문서에 필요한 논리적 구성 요소와 순서를 기획합니다.

- **담당 모듈:** LLM (Large Language Model)
- **입력:** 사용자의 원시 데이터 (텍스트, 수치, 이미지 파일 등)
- **동작:** GNN 모델이 학습한 제한된 카테고리(`Title`, `Text`, `Figure`, `Table` 등) 내에서 필요한 노드(Node)의 종류와 엣지(Edge/순서)를 정의합니다.
- **JSON 상태:** 좌표나 크기 정보 없이, 구조적 뼈대만 존재합니다.

```json
{
  "nodes": [
    { "id": "n1", "type": "Title" },
    { "id": "n2", "type": "Text" },
    { "id": "n3", "type": "Figure" }
  ],
  "edges": [
    { "source": "n1", "target": "n2" },
    { "source": "n2", "target": "n3", "relation": "next_to" }
  ]
}
```

### Step 2. 설계: 레이아웃 좌표/크기 계산 (Spatial Arrangement)

기획된 뼈대를 바탕으로, 학술 문서의 격식에 맞는 최적의 공간 배치를 수행합니다.

- **담당 모듈:** GNN (Graph Neural Network) 기반 Layout-Graph 모델
- **입력:** Step 1에서 생성된 뼈대 JSON
- **동작:** 각 노드에 실제 좌표(`x`, `y`)와 크기(`w`, `h`)를 계산하여 부여합니다.
- **JSON 상태:** 빈 공간들의 위치와 크기가 확정된 **'도면'** 이 완성됩니다.

```json
{
  "id": "n2",
  "type": "Text",
  "box": [10, 50, 200, 100]
}
```

### Step 3. 시공 & 인테리어: 콘텐츠 최적화 및 매핑 (Content Refinement)

확정된 도면(공간)의 크기와 용도에 맞게 실제 콘텐츠를 다듬고 배치합니다.

- **담당 모듈:** LLM (텍스트 최적화) & CLIP (이미지 매칭)
- **입력:** Step 2의 도면 JSON + 사용자의 원시 데이터
- **동작:**
  - **[LLM]:** 할당된 `box`의 크기(ex. 작고 좁은 칸)를 인지하고, 그 분량에 맞게 원본 텍스트를 요약/확장합니다.
  - **[CLIP]:** `Figure` 노드와 인접한 텍스트의 맥락을 분석하여, 사용자의 이미지 풀(Pool)에서 가장 유사도가 높은 이미지를 선별 및 매핑합니다.
- **JSON 상태:** 모든 콘텐츠가 채워진 **'최종 통합 JSON'** 이 완성됩니다.

```json
{
  "id": "n2",
  "type": "Text",
  "box": [10, 50, 200, 100],
  "content": "2025년 반도체 시장은 전년 대비 15% 상승하며..."
}
```

### Step 4. 렌더

완성된 단일 데이터 소스(JSON)를 바탕으로 사용자에게 최종 결과물을 시각화합니다.

- **담당 모듈:** Next.js / React (프론트엔드)
- **입력:** Step 3의 최종 통합 JSON
- **동작:** 전달받은 JSON 스키마를 읽어 브라우저 상에 오버플로우 없이 컴포넌트를 렌더링합니다. (단일 JSON을 텍스트와 차트가 공유하여 수치 불일치 원천 차단)
- **출력:** 사용자가 피드백을 주거나 PDF/HTML로 다운로드할 수 있는 최종 학술 보고서.
